# 统一固件来源与操作栏设计

## 目标

固件提取页面用一个来源区域承接本地固件和 HTTP(S) 地址，并在来源就绪后提供读取信息、提取文件和停止操作三个明确动作。

## 交互

- 来源输入框接收 HTTP(S) 地址；“选择本地文件”通过原生选择器获得本地来源。
- 本地来源不会在页面显示真实路径，只显示“已选择本地固件”。输入地址或选择本地文件都不会自动发起检查。
- 来源就绪时显示 `读取信息`、`提取文件`、`停止操作`。读取信息根据来源类型调用现有检查命令；读取成功后显示分区。提取文件仅在读取成功且至少选中一个分区时可用；停止操作仅在运行中可用。
- 输出目录仍由原生目录选择器选择，且不在页面显示本机路径。

## 边界

不增加或修改 Rust command。远程来源仍只能是 HTTP(S)，本地路径仍只来自原生选择器，前端不把本地绝对路径呈现给用户。

## 验收

- 页面不再有本地/远程模式切换与“检查地址”独立按钮。
- 本地选择仅让“读取信息”可用，点击后才调用 `firmware_inspect_local`。
- HTTP(S) 输入仅让“读取信息”可用，点击后才调用 `firmware_inspect_remote`。
- 操作栏始终包含读取信息、提取文件、停止操作；提取/停止按状态禁用。
